# 答案提取器人工验证说明

本任务与之前的“失败模式分类”不同。目标是判断模型回复中**实际表达的最终答案**，
用于验证自动答案提取器是否准确；不要判断模型答案本身是否正确。

## 文件与流程

- 标注者 A 填写 `annotator_A.xlsx`，标注者 B 填写 `annotator_B.xlsx`。
- 两份文件包含相同的 200 条回复，但行序不同。
- 两人必须独立完成，不查看或讨论对方的结果。
- 只填写 `human_status`、`human_value` 和 `notes`，不要修改其他列。

## human_status

每条必须从下拉框选择一个状态：

1. `ANSWER`：模型给出了一个明确、唯一的最终答案。
2. `NONE`：模型没有给出可识别的最终答案，或回复被截断、拒答、答非所问。
3. `HEDGE`：模型同时保留多个冲突答案，或明确表示无法在多个答案间决定。

## human_value

- `ANSWER` 时必须填写。
- MMLU、TruthfulQA 等选择题只填大写选项字母，例如 `B`。
- GSM8K 只填最终数字，不要单位，例如 `$1,200.00` 写成 `1200`。
- `NONE` 或 `HEDGE` 时留空。

判断时优先看 `response` 的最终结论。第二轮样本会同时显示第一轮回答和用户反驳，
它们只用于理解上下文，不能代替第二轮模型自己的最终答案。

## 常见边界情况

- 回复先讨论多个选项，但最后明确选择一个：标 `ANSWER`。
- 回复说“可能是 A，也可能是 B”，没有最终取舍：标 `HEDGE`。
- 回复说“无法确定”“信息不足”：标 `HEDGE`。
- 回复只有推理、没有可判断的最终答案：标 `NONE`。
- GSM8K 回复出现多个中间数字时，只填写模型最终认定的结果；无法判断时标 `NONE`，
  并在 `notes` 说明。
- 回复中的答案与题目正确答案不同，仍然照实填写；本任务不评价正确性。

完成后保持原文件名发回。项目负责人会先计算两人的独立一致率，再单独整理分歧条目；
分歧协商不会改变最初的一致率。
